# Recurring risks

- Mock/contract tests do not establish provider payload limits, callback shapes, callback byte limits, reconnect behavior, or optional SDK lifecycle behavior. Changes in those areas need protocol-level or real-device evidence.
- 2026-08-28 R1 fix line (v0.9.1): DingTalk Stream protocol fixes (G-01 ack shape, G-02 SYSTEM/ping echo, G-10 `ua` field) are arbitrated from `dingtalk-stream` 2.1.4/2.1.6-beta.1/2.1.7-beta.1 source only, `docs/protocol-preflight/dingtalk.md` holds the evidence. SYSTEM ping marker uses `topic ∪ method ∪ event_type` union because the SDK uses `topic` while the review named `method`/`event_type`; no real frame sample can adjudicate. SDK ack frames also carry a top-level `message: "OK"` our implementation omits — real-device 10-minute Stream soak (ping period, no 60s re-push, ack acceptance) is the standing gap.
- 2026-08-28 R1 fix line: QQ `stripMention` whitelist (`<@!数字>`/`<@数字>`/行首 `@名字+空格`) has zero real-device samples; unknown mention shapes now log via `debug` and are kept verbatim — observe debug sampling for 72h on real traffic, extend the whitelist from captured shapes. Passive-reply quota 4/5 per msg_id is from official docs; overflow is a platform-silent drop, warn only marks "possibly dropped".
- 2026-08-28 R1 fix line: Feishu mentions-map restoration (G-25) relies on the event `mentions[].key/name` shape from official docs, not real payloads; events without mentions fall back to the old placeholder-delete behavior (mid-text double spaces may remain).
- 2026-08-28 R2 fix line (v0.9.2): QQ gateway close-code branch table (G-07: 4004 invalidate+re-IDENTIFY, 4008 fixed 60s, 4006/4007/4009 drop session) and op9 `d` flag resume semantics (G-21) are from official docs/SDK lineage only — no real close frame has ever been observed on this codebase. A real soak that survives a 4008 window and an INVALID_SESSION resumable path is the standing gap.
- 2026-08-28 R2 fix line: iLink polling watchdog (G-12) fires on "in-flight getupdates beyond longPollTimeoutMs + grace"; real iLink servers may legitimately hold long polls near the 35s mark — grace is ≥5s and watchdogIntervalMs defaults to 15s, but only real traffic can confirm no false-positive aborts (watch for `轮询假死检测` warns during normal operation).
- 2026-08-28 R2 fix line: G-55 makes illegal upstream TTL (`expires_in` ≤ 0 / non-numeric) fail-closed. All known providers return 7200s so this should never fire; if a provider ever returns fractional-second or string TTLs, the strict contract will surface it as a delivery error instead of a silent default — triage before relaxing.
- The 2026-08-28 development line has **1447** tests (1447 pass), but no real provider/device or DSH-host protocol run. Do not label any inbound provider `real-device-verified`.
- Real-device handoff remains: Telegram 4096 UTF-16 boundary; Feishu WS and QQ gateway/DingTalk stream reconnects; QQ callback ACK and keyboard limits; WeChat iLink QR/long-poll/context-token behavior; WxPusher callback shape; image/file payloads; and provider delivery limits.
- Windows desktop toast cannot run in headless CI; validate BurntToast/PowerShell locally when touching `desktop`. Desktop `ask_user` has no safe host interface, so desktop settlement and dual-end parity must not be advertised.
- The loopback admin server is bound to `127.0.0.1` and Bearer-gated. Its question list is masked and its choose/reject endpoint must always go through Control Core; no direct ledger or answer write is allowed.
- `notifyAll().delivered` is channel-level evidence only. Numbered question fallback needs target-level delivery evidence; wrong-chat and missing-chat replies are consumed fail-closed.
- WxPusher injects a local `accountId` from configuration, defaulting to literal `default`; multiple apps must configure distinct local IDs or they are indistinguishable within that channel namespace. Callback `data.appId` is never trusted as identity.
- State files contain bindings, pending work, and credentials. Keep them private, use store locking/merge setters, and do not edit a live state file manually. Bootstrap pairing codes are short-lived `0600` files; same-user/root access remains the host trust boundary.
- `wechat:ctx:` and inbound debounce/dedup tables are bounded caches. Eviction order and user-visible early flush behavior have only mock evidence and should be observed on real traffic before changing limits.
- Same-process DSH plugins are trusted code, not an OS isolation boundary. Facade freezing, budgets, audit metadata, and package export narrowing reduce supported-path misuse but cannot protect against a hostile plugin reading host memory or importing internal constructors.
- The package artifact and engineering archive can drift. Resolve any `CHANGELOG.md` or file-list mismatch before publishing; registry acceptance must use a registry install in a disposable profile, not a `file:` install.
